# Best-practices audit

How this app measures against the owner's PWA best-practices guide (the vault's `seats/builder/pwa-best-practices/`, its `checklist.md` and the sections it points to) and the library guide's rule for shared code. Written against `main` at commit 12edd04 (version 1.0.1, 2026-10-10). Docs only: no source file was changed to write it.

How to read it:

- Status is `pass`, `fail` or `n/a`. A checklist line with several parts is `pass` only when every part passes or does not apply; the evidence names the part that fails.
- Evidence is a `file:line` in this repo, a command with its output, or the reason a row does not apply. Every `file:line` was checked to exist at the commit above. Line numbers move as the code does, so treat them as a snapshot.
- Every fail has its smallest fix and a size: XS (a few lines, one commit), S (one small story), M (one story with new files and tests), L (needs splitting).
- Scope: this repo ships one web build (a PWA on GitHub Pages at `/rotator-cuff-pt/`, `vite.config.js:10`) and the same build wrapped by Capacitor as an Android app (`capacitor.config.json`, `android/`). The Android build skips the service worker and uses a relative base (`vite.config.js:10`, `vite.config.js:15`), so PWA rows are judged on the web build. The Android shell has no rule of its own in the checklist; it is `n/a` where a row is about the service worker, the manifest or Pages. There is no Python or other server: data is only in IndexedDB (`README.md:5`).
- `docs/module-map.md` already ranks the code splits for parallel work. They are not repeated here; the Modules row points to them.
